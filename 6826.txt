- I have a Windows server working as a domain controller with active directory domain services installed

Objectives
- Configure a windows file server
- manage nfts and share permissions
- control access to files through active directory integration

File server
- computer or server that stores files in one central place and allows computer to access files over the network
- it also controls who can access which files
- multiple users can access it at the same time
- keeps files available even if someone's computer is turned off 

How it work in AD
- Domain controller - stores user acc, groups and permissions and authenticates users when they login
- File server is a domain joined server which hosts shared folders and uses AD for access control
- Domain users - who login with domain credentials access file based on permissions

How it works in real time
1. User logins with domain credentials
2. Domain controller authenticates user
3. User accesses the file share such as at \\fileserver01\HR
4. File server checks permissions and sees who the user is from AD
5. Checks share permissions and NFTS permissions on the file share
If permissions match then access is allowed 
Other wise access will be blocked

NFTS vs shared permissions
Windows file permissions
NTFS and share 
tell you who can access files and what they can do
work together but apply in diff situations

New Technology File system - locally or over the network
Permission levels
1. Full 
2. Modify
3. Read and execute
4. List folder contents
5. Read Open and view files
6. Create or modify files

Share permissions
control access when folder is shared over the network
only through a network share
\\FileServer\SharedFolder
1. Full
2. Change - read, write, modify
3. Read - view file and subfolders, run programs

Share permissions determine initial access
